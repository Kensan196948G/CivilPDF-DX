### 1.2 総合判定（改善前）

**条件付き利用可（要重大修正）**

- 理由: 機能・テスト・運用基盤はパイロット水準を超えているが、(a) 認可欠落による全データ横断参照、(b) M365 非対話ログインの認証バイパス、(c) 秘密値デフォルト、(d) 監査ログの DB 永続化不足、(e) 本番 DB が SQLite の単一障害点、が本番 600 名規模への展開を阻害する。
- 判定基準: 「本番利用可」には重大セキュリティ修正・認証強化・DB移行・監査・運用検証の完了が必要。現状は**限定パイロット（数十名・単一組織）なら条件付きで利用可**。

### 3.3 AI 方針

- チャット追加を目的化しない。**時間削減・検索/判断支援・説明可能性・安全性・費用対効果**で評価する
- 実装済み: 文書分類（図面種別/工事種別）、構造化抽出（工事名/金額/工期）、承認者向け要約 — いずれも Claude Haiku ベースで低コスト
- 不要領域（ルール/検索で十分）: ファイル名規則チェック、電子納品フォルダ構成チェック、保持期間判定、重複検出、PDF/A 判定 — AI ではなく決定的ルールで実装すべき
- 必要な設計（Phase 3）: RAG（ベクトル埋め込み＋引用・信頼度）、構造化抽出のスキーマ検証、予測/異常検知（保存期限・承認遅延）、モデル構成（Haiku 既定・Sonnet 選択可）、人間承認、権限制御（文書アクセス権をプロンプトへ伝播させない）、プロンプトインジェクション対策（命令境界・出力検証）、個人・機密情報保護（最小化・マスク）、モデル/プロンプト/入出力の監査、誤判定時の責任分界（AI は補助、最終判断は人間）、利用量・予算上限（月次トークンキャップ）、停止手段（キルスイッチ）

### 5.2 セキュリティ・データ保全の実装（#122）

1. **RBAC 一元化**（services/access_control.py）: ADMIN/MANAGER=全件、ENGINEER/VIEWER=所有文書＋所属プロジェクト。文書一覧/詳細/ダウンロード/タイムスタンプ/削除・プロジェクト・ワークフロー・リビジョン・Editor・電子納品・検索・AI・統計・組織メンバーに適用。未許可は 404 で存在を秘匿
2. **トークン種別強制**: access/refresh の type を検証（refresh token を API 認証に使用不可）
3. **秘密値 fail-fast**: 本番（DEBUG=false）で SECRET_KEY / TIMESTAMP_HMAC_KEY がデフォルト値なら起動失敗
4. **M365 ブリッジ既定拒否**: M365_ALLOWED_NETWORKS 未設定なら 503。X-Forwarded-For は TRUST_PROXY_HEADERS=true 時のみ採用
5. **アップロード強化**: PDF マジックバイト検証・プロジェクト所属検証・サイズ制限付きストリーミング保存・Content-Disposition filename サニタイズ
6. **文書の論理削除**: deletion_requested_at + archived 化（物理削除はバッチに委譲）。一覧からは非表示
7. **ワークフロー順序強制**: 前ステップ未承認の後続ステップは 409
8. **監査 DB 永続化**: ログイン成功/失敗/ロック・パスワード変更・文書/ユーザー/プロジェクト/ワークフロー/組織/AI 操作をハッシュチェーン付き監査ログへ記録
9. **ログインロックアウト**: 5回失敗で15分ロック（Alembic migration i1j2k3l4m5n6）＋管理者 unlock
10. **パスワードポリシー**: 8文字以上＋文字種2種以上
11. **追加防御**: ユーザー削除は文書所有時 409（無効化を推奨）、Editor sidecar 2MB 上限、リビジョン PDF 検証・サイズ上限、組織メンバー一覧を管理者限定
